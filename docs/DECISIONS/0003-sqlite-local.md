# ADR 0003 — SQLite local para persistência comunitária

- **Estado:** aceita para desenvolvimento local; nenhuma hospedagem persistente foi escolhida.
- **Contexto:** PostgreSQL foi a implementação anterior. O projeto ainda não tem uma conexão de banco acessível no Vercel; o frontend pode ser servido enquanto `/api` retorna 503. O requisito desta fase é iniciar e testar todos os fluxos locais sem serviços externos.
- **Decisão:** manter Bun 1.4.3 + Elysia 1.4.x e usar `bun:sqlite` sem ORM. O caminho default é `.local/spinda-stop.sqlite`, relativo à raiz do repositório. `SPINDA_DB_PATH` permite configurar outro arquivo local. Os testes criam bancos temporários e migram schema real.
- **Esquema:** UUIDs são gerados pela API em texto; UTC usa ISO texto; booleanos usam inteiro; JSON validado por SQLite usa texto; blobs guardam dados cifrados. Constraints, foreign keys, índices parciais e triggers preservam o modelo de domínio. O runner versiona checksums e só roda por comando explícito.
- **Transações/conexões:** uma conexão local com `foreign_keys=ON`, WAL, `synchronous=FULL` e `busy_timeout=5000`. A camada assíncrona serializa consultas e usa `BEGIN IMMEDIATE` para atomicidade; não promete escrita por várias instâncias ou em network filesystem. SQLite não tem GRANT; API e runner compartilham o usuário do sistema operacional com acesso DDL ao arquivo.
- **Dados existentes:** o repositório não contém arquivo de banco e os metadados de ambiente do projeto Vercel inspecionado não mostraram `DATABASE_URL` nem `DATABASE_MIGRATION_URL`. Isso não prova ausência de um banco em outra conta. Nenhuma fonte PostgreSQL foi acessada, apagada ou exportada; se uma base com dados for localizada, ela precisa de backup e plano de transferência isolado antes de qualquer mudança.
- **Hospedagem:** Vercel Functions não têm filesystem local persistente/compartilhado. Os handlers retornam `503 persistent_storage_required` antes de abrir SQLite. Nenhum serviço de banco foi contratado e nenhum deployment foi criado. As opções de host persistente ficam documentadas em [SQLite local](../SQLITE_LOCAL.md).
- **Consequências:** desenvolvimento, integração e fluxo de API deixam de depender de PostgreSQL/Docker; são adicionados comandos de migração, backup, restauração e reset seguro. Rate limit local e limpeza horária requerem um processo local persistente. Publicação comunitária continua bloqueada até decidir hospedagem, backup, rate limiting distribuído e limpeza agendada.
- **Referências:** [Bun SQLite](https://bun.sh/docs/runtime/sqlite), [SQLite foreign keys](https://www.sqlite.org/foreignkeys.html), [SQLite WAL](https://www.sqlite.org/wal.html), [SQLite PRAGMAs](https://www.sqlite.org/pragma.html) e [limites do SQLite na Vercel](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel).
